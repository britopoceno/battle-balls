## Story

**Como** desenvolvedor executando o **passo 0** do plano de construção da Fase 4
(`docs/architecture-e4.md` §10),
**eu quero** criar `src/net/protocolo.ts` — o vocabulário completo das mensagens que atravessam o fio,

     | { t: 'cast'; ballIndex: 0 | 1; slot: 'ability' | 'ult'; dx: number; dy: number; mag: number }
     | { t: 'pong'; id: number }

6. **`{t:'cast'}` NÃO tem campo `tick`, e a ausência é a decisão** (§4.1). Quem carimba o tick é o

   escolher no passado, e o servidor não revisita o passado. O comentário no tipo deve registrar o porquê,

   `match/types.ts`.
7. **Mensagens servidor → cliente**, vocabulário fechado, cobrindo as quatro fases da partida e a rodada:

     | { t: 'prazo';       terminaEmMs: number }                        // §3.4 — o relógio é do servidor
     | { t: 'rodadaInicio'; estatico: EstaticoDaRodada }                // §5.1, classe 1
     | { t: 'snap';        s: Snapshot; seq: number }                   // §5.1, classe 2
     | { t: 'rodadaFim';   resultado: ResultadoRodada }
     | { t: 'erro';        motivo: string }                             // Transicao.erro pelo fio
     | { t: 'ping';        id: number }
   ```
   `Snapshot` e `EstaticoDaRodada` podem ser declarados aqui como tipo e **preenchidos** em `e4.2` — o
   protocolo é o dono do vocabulário, `net/snapshot.ts` é o dono da produção.
8. **Nada é redefinido.** `Decisao`, `VisaoPartida`, `ResultadoRodada`, `Jogador` vêm de `match/types.ts`;

   repetindo, e reprova a story.
9. **Setas respeitadas** (§2.2): `net/` importa **só tipos** de `sim/` e `match/`; **não** importa de
   `tools/`, `client/`, `bot/` nem `chars/`. Verificável por grep.
10. **Vocabulário FECHADO**, no precedente explícito de `AimSpec` (`e2.2`): estender a união é ato
    deliberado e revisado, não acidente. O comentário no topo dos dois tipos deve dizer isso.
11. **Um aviso-invariante no topo do arquivo**, no padrão dos avisos de `debt.6`/`debt.7` em
    `sim/types.ts` — os que já provaram que comentário no lugar certo evita reincidência:

    > No modo conectado o cliente **não** chama `step()`. É isso, e só isso, que faz o modelo sobreviver
    > ao resultado de `architecture-e4.md` §1.5: Node e Chrome divergem em bits na mesma simulação
    > (`Math.atan2`/`sin`/`cos` diferem entre engines). Qualquer "otimização" futura que faça o cliente
    > simular reabre esse problema, e reabre em silêncio — predição funciona 99% do tempo e falha
    > exatamente quando o `atan2` de uma Muralha cai do lado errado.

12. **`{t:'entrar'}` carrega identidade de assento — buraco encontrado pelo @po na validação.**
    `architecture-e4.md` §6 afirma que *"reconexão sai de graça"*, e a afirmação é verdadeira quanto ao
    **estado** (o cliente não guarda autoridade nenhuma). Mas ela não é verdadeira quanto à
    **identidade**: com `{t:'entrar', sala}` e nada mais, o servidor não consegue distinguir o jogador 0
    voltando de um terceiro sujeito abrindo o link. Os dois chegam idênticos no fio, e o segundo deveria

    Como o AC 10 declara o vocabulário **fechado**, deixar isso para `e4.4` obrigaria a estender a união
    depois — exatamente o que o AC 10 diz que não pode ser acidente. Portanto entra agora:
    ```ts
    | { t: 'entrar'; sala: string; assento?: string }   // `assento`: segredo devolvido no primeiro
    ```                                                  // `{t:'sala'}`, reapresentado ao reconectar
    O servidor gera o segredo de assento no primeiro `{t:'sala'}` (stream próprio, como o id da sala) e
    o cliente o reapresenta. **Esta story só declara o campo e o comentário**; quem o gera, guarda e
    confere é `e4.4`. Declarar sem implementar é o certo aqui — é o mesmo padrão de `Snapshot`, que
    nasce como tipo em `e4.0` e ganha produtor em `e4.2`.
13. **Escopo de arquivos.** Esta story cria **um** arquivo e altera **zero**: `src/net/protocolo.ts`.

## Dev Notes

### Por que o protocolo vem antes de qualquer comportamento (fonte: `architecture-e4.md` §2.2, §2.3)

A régua desta fase é *"o jogo mudaria se ninguém estivesse conectado?"*. Se não muda, é transporte, e
transporte não entra em `sim/` nem em `match/`. O protocolo é onde essa fronteira vira arquivo.

`net/` e `server/` são pastas diferentes por um motivo operacional, não estético: `net/sala.ts` (`e4.3`)
precisa rodar nos dois lados da fronteira, e `ws` não roda no navegador. Se a máquina de estados da sala
importasse `ws`, testá-la exigiria socket, e o `sim:check` — processo único, sem rede — não poderia
cobri-la. Mesmo precedente de `tools/harness.ts`, extraído em `e2.0` para haver **uma** definição do laço
com **dois** consumidores.

### Por que `{t:'cast'}` não carrega `tick` (fonte: §4.1)

Hoje o cliente decide o tick do próprio comando (`client/main.ts:311`):

```ts
pendentes.push({ tick: world.tick + INPUT_DELAY_TICKS, ballId: bola.id, ... })
```

No modo conectado o campo **sai do fio**. O cliente envia intenção; o servidor carimba
`tickAtual + ATRASO_ALVO_TICKS`. Duas razões, em ordem de peso:

1. Um tick escolhido pelo cliente é um tick que o cliente pode escolher no passado. Castar "no tick 300"
   com o servidor no 340 é retroceder a simulação — e o servidor não pode conhecer o futuro (o modelo
   morto do GDD §8) nem revisitar o passado.
2. `Command.tick` continua existindo e continua igual em `sim/types.ts`. Muda **quem preenche**, não o
   tipo. `sim/step()` segue consumindo `commands` sem saber se o número veio de um humano local ou de um
   socket.

### `ballIndex`, não `ballId` (fonte: §8.1)

O cliente manda o índice da **sua** bola (0 ou 1), nunca o `ball.id` do mundo. É o que impede, por
construção, castar bola alheia: o servidor resolve `ballIndex → ballId` sabendo o assento da conexão e o
lado que `ladosDaRodada` deu ao jogador **nesta** rodada (§5.3 de E3 — jogador ≠ lado). É a única linha
genuinamente nova de anti-cheat da fase inteira, e ela nasce aqui, como forma do tipo.

### O que esta story explicitamente NÃO faz

- **Não produz snapshot.** `Snapshot` é declarado como tipo; quem o produz é `net/snapshot.ts` (`e4.2`).
- **Não muda `INPUT_DELAY_TICKS` no cliente.** A constante existe aqui; ligá-la é `e4.1`.
- **Não abre socket.** `ws` entra em `e4.4`, com `package.json` (R-05 aguarda ratificação — ver
  `architecture-e4.md` §12).
- **Não decide `SNAPSHOT_HZ`.** Ver R-03.
